# Lumina

A premium, multi-category e-commerce storefront: **Angular 18 + UI5 Web Components**
(`@ui5/webcomponents-ngx`) frontend, **Laravel 11 + Sanctum** JSON API backend. Quiet,
editorial visual identity — cream/beige surfaces, sage green accent, charcoal text — over
a real catalog with smart categories, search/filtering, wishlist, cart, product comparison,
and content-based personalized recommendations, all working for guests as well as
registered accounts.

```
backend/           Laravel API — see backend/README.md
frontend/           Angular + UI5 SPA — see frontend/README.md
API_CONTRACT.md     The shared contract both sides implement exactly. Read this first
                    if you're changing either side — it's the source of truth for every
                    endpoint, JSON shape, auth header, and design token.
```

## Running it locally

Requires PHP 8.2+ with Composer, and Node.js 18+ with npm — install both before starting.

```bash
# Terminal 1 — API on http://localhost:8000
cd backend
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed
php artisan serve

# Terminal 2 — SPA on http://localhost:4200
cd frontend
npm install
npm start
```

Then open `http://localhost:4200`. A demo account is seeded: `demo@lumina.test` / `password`
— or just browse as a guest, since cart/wishlist/recommendations all work without logging in
(guest state is a `localStorage` UUID sent as `X-Guest-Token`, and merges into your account on
login/register).

## How the two sides agree with each other

Both `backend` and `frontend` were built independently against `API_CONTRACT.md` rather than
one generating code from the other, so that contract is the only place endpoint paths, JSON
field names, and the cream/sage/beige/charcoal design tokens are defined. If you add or change
an endpoint, update the contract first, then both sides.

Auth is plain Sanctum bearer tokens (`Authorization: Bearer <token>`), not cookies — deliberately,
since the SPA and API are separate origins and this sidesteps CORS/CSRF-cookie configuration
entirely. `backend/config/cors.php` allows the frontend's origin (`FRONTEND_URL` in `.env`,
defaulting to `http://localhost:4200`) with `supports_credentials: false` to match.

## A note on how this was built

This project was generated by an AI coding agent in an environment with no PHP, Composer,
Node, or npm installed — so nothing here has been compiled, installed, migrated, or run.
Everything was hand-written to match Laravel 11 and Angular 18 CLI conventions exactly and
was read back and cross-checked against `API_CONTRACT.md` endpoint-by-endpoint, but you are
the first one to actually run `composer install` / `npm install` against it. Expect to spend a
little time on first-run fixups (a dependency version nudge, a typo) before it's fully green.
